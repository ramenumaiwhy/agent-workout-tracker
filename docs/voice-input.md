# 音声入力の方向

## 最終的な方向

- 筋トレ記録は音声入力へ特化する。
- 画面を開く操作、開始操作、種目を選ぶ操作はなくす。
- 発話例は「ベンチプレス60キロ10回」とする。
- ジムでは手で入力する操作が面倒である。
- ジムには音楽と周囲の音がある。音声認識の聞き間違いを想定する。
- 記録後は、短い音声で記録内容を確認できるようにする。

## MVPで先に検証すること

- Siri経由の入力はまだ作らない。
- 利用者はAIエージェントへセット実績を報告する。
- AIエージェントは同じ記録を直接参照する。
- AIエージェントは過去のセット実績から次回メニューを提案する。
- 表示機能は必要最小限にする。
- 最初の表示機能は種目別の重量推移グラフとする。
- 音声入力は、記録moduleを変えずに追加できる将来のadapterにする。

## 音声入力を設計する条件

次の条件を確認した後に、Siriなどの音声入力adapterを設計する。

- ジムでエージェント画面を開く操作が継続の妨げになる。
- セット実績の項目と訂正方法が安定している。
- 音声認識の聞き間違い対策へ追加工数を使う価値がある。

音声入力adapterは、音声認識、復唱、確認継続、通信、失敗時の退避を担当する。筋トレ記録moduleへ渡す値は、MVPと同じ構造化`command`を使う。
